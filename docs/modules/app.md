# Part F local application

The CLI and loopback web application call the same production `generate`
entry point. The app uses Python's HTTP server and serves bundled HTML, CSS,
JavaScript and a font. It requires the same Python dependencies as the
pipeline.

## User flow

Run `python -m codeart.app`, then open its printed loopback address.
The six sample selections preserve E's explicit fixture identity. Editing a
sample converts it to ordinary input. Source text, shape and initial scale
are validated on submission. The app supports one active generation and
retains five runs. Page refresh can reconnect to the active run in the same
browser tab.

File-mode jobs retain the complete input alongside the extracted function.
Refreshing restores file mode, the selected candidate and its scope notice.

The server runs generation in a worker thread and passes a shared Event to
the pipeline. Cancellation stops work through the module contexts and their
subprocess runners. Complete-file analysis runs in the same cancellable job
and shares its generation deadline. Completed artifacts remain available.
Shutdown requests cancellation and waits for the active pipeline to finish cleanup.

Original text and generated source use the same fixed font. Long lines
scroll without wrapping. The interface shows each validation state and skip
reason, coverage, grid, actual scale, attempts, elapsed time, diagnostics,
first token difference and layout attempt history. Verification failures
are labeled for review, including when partial source can be downloaded.
Changing inputs clears the prior preview.

For a complete C file, enable **Extract from a complete C file**, click
**Find functions**, then choose a passing candidate. The scope notice is shown
only in file mode. The selected function is rechecked by A when generation
starts; samples and plain `--source` input remain the v1.4 single-function
path.

## HTTP interface

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/` | Local application |
| GET | `/api/samples` | Names and exact built-in sources |
| GET | `/api/environment` | Python, platform, compiler and package versions |
| POST | `/api/generate` | Submit source, shape, scale, optional sample name, and optional `file_mode` + `function` |
| GET | `/api/jobs/<id>` | Job state, original source and result summary and revision |
| POST | `/api/prepass` | Locate candidate functions in a complete C file; returns candidates, selection and ignored ranges |
| POST | `/api/jobs/<id>/cancel` | Request cancellation |
| GET | `/api/jobs/<id>/source.c` | Download generated bytes with LF line endings |
| GET | `/api/jobs/<id>/report.json` | Download diagnostics, metrics and checks |

Requests are limited to 1 MiB. The server listens on 127.0.0.1 and rejects
foreign browser origins on mutation requests. Paths map to explicit assets
or in-memory jobs. The browser renders source and diagnostics as text.

### Complete-file extraction

`/api/prepass` accepts `{"source": "..."}` and returns candidate definitions
with `name`, line/column ranges, `a_status` and A's diagnostic. A candidate is
eligible only after A analyzes the extracted text. `main` and functions inside
conditional preprocessing regions are ineligible. The locator masks comments
and literals before matching braces, so directive-looking text inside them is
ignored; it normalises CRLF/lone CR and strips a leading UTF-8 BOM. It is
lexical, not a full C parser: K&R-style definitions and some macro-generated
declarations may not be listed.

`/api/generate` with `file_mode: true` returns HTTP 202 with a job ID before
the prepass runs. The job replaces the source with the selected function,
clears the sample selection and attaches the prepass result. Extraction
failures are finished jobs with `status=FAILED`, all four checks `NOT_RUN`,
and the extraction error in `prepass`. Invalid request fields still return
HTTP 400. The separate `/api/prepass` inspection endpoint is synchronous.
Snapshots retain `source` as the extracted function and add `input_source`,
`file_mode` and `function` for page restoration.
The report includes `ignored_lines` and
precise same-line `ignored_segments`. Only the extracted function is verified;
`generate()` and A still accept exactly one self-contained function.

Reports include `status` (`OK`/`FAILED`/`CANCELLED`) and the font identity
taken from `mask.font_metrics.font_id`. A failed `--file` extraction keeps the
same top-level report shape: `status=FAILED`, `revision`, `prepass` with the
error, and all four checks `NOT_RUN`.

`code_fill_ratio` is the renderer's token coverage (non-space token ink over
allowed cells). Below 10%, the UI displays `Token density is low; filler
comments occupy most allowed cells.` It is informational and does not affect
checks, layout or size.

## Font

The bundled file is Roboto Mono Regular from
[the Roboto Mono project](https://github.com/googlefonts/RobotoMono).
Copyright 2015 The Roboto Mono Project Authors. The complete SIL Open Font
License 1.1 is included in `codeart/web/fonts/OFL.txt`. The font was obtained
from `fonts/ttf/RobotoMono-Regular.ttf` in that project's main branch.

The app's CSS uses `font-size: 12px`, zero letter spacing and disabled
ligatures. The result's `cell_aspect` sets line height, with `2ch` as the
initial fallback. This gives a physical character width to
row-height ratio of 0.5, matching B's default `FontMetrics`. The font is
served locally and the application needs no external font service.

## Verification and limits

HTTP tests exercise validation, fixture eligibility, source and report
downloads, cancellation, overlap rejection and missing results. CLI tests
exercise a real sample through the production pipeline. Source-module
tests cover 18 generated samples and 144 behavior comparisons.

The server is a local course-project tool. Results are held in memory.
The CLI accepts initial scale values from 1 to 4 and the web application
provides the same range. C's automatic growth still observes its own grid,
attempt and time limits. Independent scaled-cat acceptance evidence
remains part of B/E's formal regression work.

## Public process utilities and evidence

A and E import shared process and build utilities from `codeart.procutil`.
The former `codeart._verification_process` module re-exports the same
symbols for compatibility with older callers.

Downloads include the realized height and scale in their names, for example
`case_max2_cat_h32_s1.c`. JSON reports record the tested commit and dirty
worktree state. Keep fixed and grown evidence separate. A CLI report records
the revision alongside check results and attempt history.

The default full CI runs on Ubuntu for every PR, using Python 3.12,
clang-18 and libclang 18.1.1. The additional macos-15 full job runs on
manual dispatch or a PR carrying the `macos-ci` label.
It prints `clang --version` and records the complete environment. The test
count guard compares collected counts against the PR base or previous main
commit. A collection error fails the guard.
